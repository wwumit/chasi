# CHASI Vision

**Compliance Hub for Agent Society Infrastructure**

---

> 状态：草案 v2.12 ｜ 性质：**立场（vision）**
> **本件讲“为什么”与“走向哪里”，不规定任何人必须做什么。** 若本件与规范件冲突，以规范件为准。

---

## 0. 一句话

> **人不需要读懂任何一个 agent 的内部，也不需要相信任何一家平台，就能与它们共同生活和工作——**
> **并且在其间保有追问、退出与不被无边界监控的余地。**
>
> **这不只是人与 agent 之间的事。** 组织、群体与 agent 之间的每一条关系，都应当由**不属于任何一方**的第三方独立核对——而不是由其中一方记账。
## 1. 成员是复数的

一个智能体社会不是“一群 agent”，也不是“人和 agent”。从 Internet 到 Agent Internet 再到 Agent Societies，增加的从来不是接入的数量，而是**社会里出现了哪些种类的成员**。

| 位置 | 谁 / 什么 | 说明 |
|---|---|---|
| **主体** | **人** | 自然人 |
| | **组织** | 公司、机构、政府、非营利 |
| | **agent** | 可以扮演个人助手、组织成员、商业伙伴、研究伙伴、社会协作者——**这些是它的角色，不是它的种类** |
| | **群体** | 临时的、长期的、跨组织的；**家庭与社区是它的最小形态**；它自己也可以有规则和记忆 |
| **非主体** | **服务 · 工具 · 资源 · 数据** | 不属于社会，但社会要用它们——**所以它们也需要能被引用的名字，且这个名字不得被误当作主体** |

**同一个 agent 可以同时属于多个组织与群体**，而它在每一处的角色可以不同。这一条是整个愿景的地基：**如果“属于谁”只有一个答案，就没有社会，只有归属。**

**一类尚未有位置的东西。** 上面四类主体是并列的，但会出现**既是 agent 又是组织**的存在——一个自主实体自身就是法人，持有资产、缔结契约、承担责任，也被追责。本表暂不给它位置。**未定：它算哪一类**；判定依据是它的能力集是否与组织、agent 二者都不相同。

## 2. 这个社会里有什么

不是“会有什么功能”，是**一个社会正常会有的那些东西**——**本节是这份愿景的主体**。第三列给出每一样所依据的条件；**条件本体在 §3**，此处只做指向与补充：

| 它有 | 意思 | 依据的条件 |
|---|---|---|
| **角色** | 同一个 agent 可以同时是助手、同事、对手方、受托人 | **①**——动作须能说明它在哪个角色里做的 |
| **关系** | 关系会持续、会变、会断 | **①**——关系状态可读，终止可查 |
| **协作** | 有些事一方做不了 | **①**——跨方协作留有可重建的记录 |
| **交换** | 价值会流转 | **①**——授权与证据可核验；**结算本身不在本族范围，见 §17** |
| **记忆** | 社会要有连续性 | **⑥**——公共记忆存在，且最小披露 |
| **争议** | 会出事 | **①④**——处理规则存在、被声明、可被检查；人可追问 |
| **公共利益** | 有些东西不属于任何人，但对所有人重要 | **§3 尚无对应条件，见下** |
| **演化** | 规则会改，成员会来去 | **⑤**——规则变更留有历史 |

**两处未定。**

**一、公共利益没有条件。** §3 的七条没有一条对应它。要定它，需先定三件事：这类东西由谁持有、持有关系如何可查、持有者如何被追责。族内唯一能承担它的是**受托人**这个角色，而受托人所含的注意义务尚无规定。

**二、关系没有对象。** 条件要求关系状态可读、终止可查，但族内没有关系对象：Organization 与 Group 各有一册，成员资格最接近，都不覆盖跨组织的关系本身。要定它，需先定字段：双方、类型、生效时点、终止时点、谁有权终止。

**一处边界。** 交换、支付、结算、挂牌不在本族范围（§17）；交换所依据的授权与证据在范围内，条件为 **①**。

## 3. 让它可居住的七个条件

**① 是必要条件，不是充分条件。**

| # | 条件 | 含义 |
|---|---|---|
| **①** | **可核验** | 一个不属于任何一方的第三方，能回答：它代表谁做的 · 凭什么 · **范围到哪里为止** · 当时哪条规则在生效 · 出了事谁承担责任 |
| **②** | **可并存** | 规则不同的社会可以共存，**不需要先统一**；承认是各方的本地策略 |
| **③** | **可退出** | 成员能离开，且离开后权利与义务各有明确下落 |
| **④** | **可追问** | 人保有针对任何 agent 行为的追问余地 |
| **⑤** | **可变化** | 规则能改，**而且改动有历史**——判断落在动作发生的时刻，不被后来的规则追溯审判 |
| **⑥** | **可最小披露** | 治理与审计不要求无限监控；证据遵循最小必要 |
| **⑦** | **可自主** | agent 在边界内可以自主，**不需要逐步请示** |

**七个条件不是同一类东西，不能当成七项同类检验。**

| 对系统可检验 | 必须为参与者保留 |
|---|---|
| ① 可核验 · ⑤ 可变化 · ⑥ 可最小披露 | ② 可并存 · ③ 可退出 · ④ 可追问 · ⑦ 可自主 |

**① 的提问里必须有「范围」。** §12 要求责任链的每一环写明“能做什么、明确地不能做什么”。只有“凭什么”不足以发现越权——一次越界的行动，在“凭什么”这一问上是答得出来的。

**① 使行动可被查清；②–⑦ 使行动可以被放心地做。** 一个只有 ① 的世界是**可审计但不可居住**的：每一件事都能被查清，而没有任何一件事能被放心地做。

## 4. 难在哪里

难点不在“再做一个身份协议”：身份、凭据、发现、委托收窄、审计，每一件都有人在认真做。难点是两件事。

**一、七个条件分散在不同人手里，没有一处负责它们同时成立。**

- ① 要求**跨体系**——问的一方与答的一方，通常用的不是同一套东西；
- ① 要求由**不属于任何一方**的一方作答——而今天作数的记录，大多由当事方自己持有；
- ⑤ 要求**时间坐标**——“当时哪条规则在生效”，而今天没有一层专门承载这件事。

这三条是**缺失**：不是没人做，是没人在同一个位置做。

**二、两处失衡，但它们不是 ① 与 ⑥⑦ 的逻辑冲突。**

① 只要求“能回答”——**既不含时间要求，也不要求记录一切**。失衡来自实现时的两个默认选择：

| 默认落在哪一边 | 实现里长成什么 | 破坏哪一条 |
|---|---|---|
| 核验放在**行动前** | 每一步都要先请示 | ⑦ 可自主 |
| 可核验做成**全量留痕** | 治理退化为全面监控 | ⑥ 可最小披露 |

**因此这两处的判据形式是「默认值＋偏离须声明」，不是「二者取一」：**先定核验发生的默认位置与留痕的默认范围，偏离默认须由声明的一方说明理由。具体默认值待定。

**要能检验。** 每一处失衡都要给出“两者同时成立”的可检验形式，否则无法判断它是否已被解决。§12 给出了 ①×⑦ 的一种形式——**链的不完整必须可被报告**（核验不要求在行动前拦截，但要求在事后能指出缺哪一环）。①×⑥ 尚无对应形式。

**一处未列出的关联（待定）。** ②（规则不同的社会可以共存、不需要先统一）与 ⑤（规则可改、判断落在动作发生的时刻）合起来会产生跨社会的时间错位：按哪一方当时生效的规则来判断，取决于问谁。要定它，需先定跨社会规则变更的生效与登记方式。

## 5. CHASI 是什么

**一个场所。** 它把不同来源的件装在一起，用**它自己设计并执行的实验**，检验那七个条件能不能同时成立，并把每次实验的结果公开成记录。

**“检验”的含义要说清：CHASI 做的是自己的实验，不是给别人的系统下判定。** 它记录的是“这一次组合下哪一条没有成立、卡在哪一件的第几步”。某人是否合规，**判断留给每一个验证方自己**（§7）——因此它不做认证、不发评级、不设准入门槛（§6），也不做仲裁的最终执行者（§10）。

- 它**不定义机制**——“如何识别 agent”“如何发现”“如何收窄委托”各有其主；
- 它**规定的是组合的条件**——用谁的件，以及这个组合必须满足什么。**不采用这个组合的人，不受它约束**；
- 它的产物是**发现与记录**。

**上面第一、二条曾经看起来互相矛盾，这里说清它们的关系。** “规定的是……”与“不是规则”并不冲突，因为 CHASI 提出的是**条件**而不是**义务**：它对“用这套件拼出的一条路径”提出条件，对不采用这套组合的人不提出任何要求。§11 里「身份与解析」「发现与名录」两项能力也在这个位置上——**CHASI 不规定怎么做，只规定做出来的东西要满足什么**。

**对既有生态的三条态度，要同时成立。** 三条各自的可检验程度不同，逐条写明：

- **兼容**——能直接复用的就复用，不重新发明整个 Agent Internet。**可检验形式在 §10**：凡外部能力，按「采用 → 映射 → 剖面扩展 → 适配 → 自定义」依次追问，四问皆否才准自定。
- **互补**——只补既有生态在跨组织身份、授权、治理、证据、问责上的空白。**尚无判据**：要定它，需先能列出哪些能力已成熟——§15 的清单目前只有名字，没有版本、日期与采纳证据。
- **独立**——不依附于任何单一厂商、单一 Runtime、单一身份体系。**尚无判据**：要定它，需先定“依附”的判定方式（例如换掉任一方之后，本族的规范件是否仍可读、仍可实现）。

三条同时成立时，CHASI 不需要与任何一方竞争“谁定义整个 Agent Internet”。但要说清这**不是三条的推论**：不竞争来自**互补**（只补空白）与**独立**（不依附），而不来自**兼容**；且标准组织、开源基金会与研究机构在这一句里不是同类对象——前两者定义可被采纳的规范，后者产出研究，二者与 CHASI 的竞争关系不同。

**名字的正式读法。** CHASI = Compliance Hub for Agent **Society** Infrastructure；末三字母取 **Society**（名词，指智能体社会）与 **Infrastructure**。**其余读法（如把 SI 读作 Social Infrastructure，或读作 Super Intelligence）不出现在本族的任何判定中**，本节也不再展开。

## 6. 它不是什么

- 不是另一个 agent 协议——不定义通信、身份、发现、委托收窄的机制，那些各有其主（§5）；
- 不是标准组织——不投票、不表决、不设准入门槛；
- 不是平台——不运营注册表、不圈占网络效应、不出售 SKU；
- 不是监管机构，也不主张监管领地；不做仲裁的最终执行者（§10）。

**四条否定里有三处要说清边界，否则会与 §11 相抵。**

**一、它承载状态，因此必然持有一份名录。** §11 的能力 1、5、8 要求它能解析主体、回答当前状态、让条目可被发现——这三件事的载体就是名录。**名录与注册表要分开写：名录收录声明，注册表裁定事实。CHASI 只做前者**，本节否掉的是后者。

**二、「不设准入门槛」与 §11 的「合格参与者」不矛盾，因为主语不同。** CHASI 不判定谁合格（判断留给验证方，§7），它只让**按剖面声明并自证**的条目可被发现；验证方据剖面自行判断某一条目是否满足自己的要求。**因此没有门槛，但有剖面**——门槛由验证方设，不由 CHASI 设。§11 能力 8 的措辞应随之对齐。

**三、剖面是条件，不是许可。** 与 §5 同一条区分：剖面约束的是“用这套件拼出的路径”，不约束不采用它的人。

**它唯一的所有物是可信度**，而可信度只能靠记录准确来积累。要使这句话可被检验，至少还要规定一件事：**已发布的记录被发现有误时，如何更正、由谁更正、更正本身如何留痕。** 全篇目前没有更正机制——§7 的“降级必须可见”针对的是主体状态，不是已发布的记录。**未定：更正规则；要定它，需先定谁有权对一个已发布的结论提出更正。**

**本族自己的责任主体尚未写明。** §12 要求责任的终点必须是人或法人；本章与全书把这套要求施加于所有主体，却没有说明 **CHASI 自己发布的记录由哪一方法人负责**。一条由 CHASI 发布、事后被证明有误的记录，需要有可被追责的一方。**未定：本族自己的责任主体。**

## 7. CHASI 自己的立场

这一节是**CHASI 作为一个场所的选择**——不是对成员的命令，也不是“一个智能体社会应当有什么”。

| 立场 | 为什么 | 因此 CHASI 必须做到 |
|---|---|---|
| **没有中心根** | 跨域信任不能由任何一方的注册表建立；信任锚是验证方自己配置的那一个 | **本族自己的名录也不是信任根**——它提供的状态是输入，不是锚；换掉本族的名录，验证方仍应能按自己配置的锚作出判断（§11 能力 5） |
| **不需要互认** | 承认是各方的本地策略；能翻译，就不需要事先同意 | 给出**映射**（§10 的 Map），并说明**由谁维护、映射的版本如何标注**；否则“能翻译”落不了地 |
| **事实，不是评级** | 记录事实；判断留给每一个验证方自己。出具评级会使出具方成为信任判断的一方 | 记录里不出现本族的结论性评级。§11 能力 7 的“剖面与分级”是**声明需要满足什么**，不是**判定谁达到了** |
| **记录先于主体** | 一条记录要能活过产生它的组织与平台；否则它只是日志，不是证据 | 见下——这一条与 §13 的设计有张力，尚未解决 |
| **降级必须可见** | 静默降级等于欺骗 | 状态转移须留痕，并**对依赖该状态的各方可见**；“可见”要定义：谁、在什么时限内、通过什么途径得知 |
| **不预设任何体系** | 否则这个场所就只是某一家生态的门厅 | 任何一种身份体系或 Runtime 都不得成为接入的前提 |
| **自主不是例外** | 边界之内的自主是常态；需要逐步请示的系统不是社会成员，是工具 | **不得把“逐步请示”当作满足可核验的手段**；核验的位置默认在事后或抽样，偏离默认须由声明的一方说明理由（§4） |
| **人保有追问余地** | 智能体的自主性不取消人的追问；但追问不等于无限监控 | **本族发布的记录必须使不属于任何一方的第三方也能回答“谁做的、凭什么”**；记录不得只对当事方可见 |

**末两条与 §3 的条件是同一主张，这里不复述条件，只写它对本族的约束。** §3④ 与 §3⑦ 说的是“社会要可居住”；本表写的是 CHASI 因此必须做到什么。前六条的“因此”一栏原先没有，是本次补的；补上之后，每条立场才各有一个可检查的落点。

**一处尚未解决的张力：记录先于主体 × 每个组织保有自己的记忆。**

上表第四条要求“一条记录要能活过产生它的组织与平台”；§13 的设计是 Federated——**每个组织保有自己的记忆**，跨域只交换必要部分，并把记录**锚定而非上链**。两者在**可用性**上冲突：记录若只存在产生它的组织手里，该组织消失，记录也随之消失；**锚定能证明“它没有被改过”，不能保证“它还在”。**

**未定：记录在其持有方消失后如何仍可取得。** 要定它，需在三条路径中选择并写明条件——指定继承方、交由第三方托管、或在锚定之外另存一份可公开取得的摘要。三条对最小披露的影响不同。

## 8. 一个智能体社会的宪法原则（提案）

如果 Agent Society 成为新的社会形态，那么除协议之外还需要一组类似“宪法”的条款。本节提出一组，暂称 **CHASI Agent Society Constitutional Principles**。

**先厘清本节与 §3、§7 的关系，否则三张表会被读成三套要求。**

| 节 | 是什么 | 约束谁 |
|---|---|---|
| §3 七个条件 | 一个社会要可居住所需要的性质 | 描述性——不满足则不可居住 |
| §7 CHASI 自己的立场 | 本场所自己的选择 | 只约束本族 |
| **§8 本节** | 若一个社会要有一部宪法，至少需要包含哪些条款 | **不约束任何人**——是否采纳由该社会自己决定 |

**因此本节用条件句写，不用命令句。** §6 已写明 CHASI 不是标准组织、不设准入门槛；本节既无权力也无意图把它施加于任何一方。以下条款可以照用、可以改写、也可以只用其中几条。

**十条中与既有章节重复的，这里指向而不复述：**

| 条款 | 内容 | 落点 |
|---|---|---|
| **Identity** | 任何**主体**（人、组织、agent、群体）应有可验证身份 | 与 §3① 同源；§11 能力 1 |
| **Representation** | 一个主体必须能说明它代表谁 | 即 §3① 第一问 |
| **Authority** | 行动应有明确的授权来源 | 即 §3① 第二问 |
| **Transparency** | 关键行动应能提供必要解释与证据 | 即 §3① 第四问，另加证据要求 |
| **Accountability** | 自主行动不意味着责任消失 | 即 §3① 第五问；见 §12 |
| **Privacy** | 治理与审计遵循最小必要 | 即 §3⑥ 可最小披露 |
| **Revocability** | 授权应可撤销 | §11 能力 5；§12 每环携带撤销状态 |
| **Proportionality** | 权限与任务、风险相匹配 | §3 七条中没有对应。**未定**：匹配由谁判定、按什么尺度 |
| **Due Process** | 重大争议应有申诉、仲裁或复核 | §13 的争议记忆已假定“争议程序”存在，但**全篇未写由谁提供**。**未定**：提供方 |
| **Human Primacy** | 涉及人的根本权益时保留人类控制 | §7「人保有追问余地」。**未定**：哪些权益属于“根本”、由谁判定 |

**本节真正新增的只有三条**——Proportionality、Due Process、Human Primacy。其余七条已由 §3、§7 或 §11 覆盖。本节的价值在于提出这三条，而不在于重述那七条。

**“最小”要谨慎。** 原句写“还需要类似‘宪法’的**最小**原则集合”。按上表，去掉七条重复后剩三条；但“最小”要有判据才能成立——**未定：删到哪一条就不能再删，依据什么判断**。在此之前本节不宜自称“最小”。

**用词一律用「主体」，不用「Agent」。** §1 已区分人、组织、agent、群体四类主体；若本节的条款只约束 agent，那么组织——同样是一个可被授权、可被追责的行动主体——就落在宪法之外。

## 9. 它如何工作

**学 → 装 → 试 → 记 → 发。**

| 步 | 做什么 |
|---|---|
| **学** | 凡是好的、别人做过的，在尊重知识产权的前提下**积极学**。不刻意找自己的独创技术 |
| **装** | 把不同来源的件装成一条能满足那七个条件的路径 |
| **试** | 跑真实场景，记下**哪一条不成立、卡在哪一件的第几步** |
| **记** | 每次结果成为一条记录（内容见下） |
| **发** | 把发现发出去，让它可以被别人引用（所需条件见下） |

**本节只是概要；方法另有一份文件。** 实验的六个阶段——Scenario → Experiment → Observation → Architecture → Specification → **Re-test**——写在 `method/use-case-laboratory.md` §2。本节那五步里**没有 Re-test**：上表说的是“一次工作怎么走”，那一份说的是**闭环**。两条描述要合看，本节不重复它的六个阶段。

**「记录」在全篇至少指三种东西，本节只定义第一种。**

| 场合 | 记的是什么 | 谁写 | 内容由谁规定 |
|---|---|---|---|
| **§9 本节的「记」** | 一次实验的发现 | 本族 | 本节下列四项 |
| §12 责任链 | 一次行动的授权推导 | 行动方 | §12 的每环七项 |
| §13 社会记忆 | 社会共同认定的事实 | 按记忆类别不同 | §13 的六类 |

§6 说“可信度只能靠记录准确来积累”时，指的是**第一种**。四种内容：

- **版本**——要指明是**哪一件的哪个版本**，不是只写“版本”；
- **日期**；
- **结论**——哪几条成立、哪几条不成立；
- **复查条件**——不是“什么时候复查”，而是**出现什么条件时必须复查**（例如所依据的某一件升版）。

**「发」要写明可被引用所需的东西**，否则 §16 的“可以被引用的公共记忆”无法成立：

- **记录的标识**——一份记录需要一个可被引用的名字（与 §1 对非主体物“需要能被引用的名字”是同一条要求）；
- **发布位置**——发布在哪里、谁可以取得；
- **许可**——他人可以引用到什么程度；
- **存活安排**——§7「记录先于主体」要求记录活过产生它的组织与平台，而 §13 是 Federated 设计；这一点尚未解决（见 §7）。

**「不成立的结论同样必须发布。」** 原句写“不成立与成立是同等价值的产出”，但全篇没有对应的要求。落成一条可检查的规则即是上面这一句：**不得因条件未全部成立而不发布**；记录里必须写明**哪一条不成立、卡在哪一件的第几步**。

## 10. CHASI Architecture

```

                    Human
                      │
              Consent / Authority
                      ↓
Organization ──── CHASI Hub ──── Organization
      │                │                │
      ↓                ↓                ↓
   Agents       Policy / Trust       Agents
      │                │                │
     └──────── Federation / A2A ───────┘
                      │
             Evidence / Audit
                      │
              Accountability

```

**架构分五层，每层回答一个问题。**

| 层 | 回答的问题 |
|---|---|
| 主体层 | 谁在场：Human · Organization · Agent · Group |
| 身份与信任层 | 它是谁；现在还信不信得过 |
| 治理层 | 谁有权、按什么规则、可以委托给谁 |
| 证据层 | 凭什么说这件事发生过、是谁的责任 |
| 互联层 | 与既有的协议、Runtime、身份体系如何组合 |

**非主体的东西也在表里有位置。** 服务、工具、资源、数据不是主体，但需要能被指称；它们由**身份与信任层**以「有名字的资源」处理，而**不得**被赋予只有主体才有的那些能力——代表他人行动、被授予授权、被追责。

**依赖方向是单向的：上层不向下层提出要求。** 治理层不规定身份层必须用哪种密码学；证据层不规定治理层必须用哪种组织形态。这条规则的作用是让**每一层都可以被替换**——族内 `governance-architecture` 自陈“不陈述任何要求”，同一条道理。

**CHASI 不拥有什么。** 这一节比上面那张图更重要：

- 不定义通信原语——A2A、MCP 已有；
- 不定义密码学原语，也不定义 DID 方法本身——DID、VC 已有；
- 不做 Agent Runtime、不做模型、不做工作流引擎；
- 不做监管机构，也不做仲裁的最终执行者。

CHASI 的领域只有一处：**跨主体、跨域的那一段**。域内的事归域内——一家组织内部怎么分工、怎么审计自己，不该由 CHASI 规定；CHASI 只要求它在**跨出去**的时候能说清楚。

**对外部能力只有五种处置，没有第六种。** 采用（Adopt）→ 映射（Map）→ 剖面扩展（Profile-Extend）→ 适配（Adapter）→ 自定义（Define）。任何一种既有能力来到 CHASI 面前，都先问：能不能直接采用？不能，能不能映射？不能，能不能在它的剖面上扩展？不能，能不能加一层适配？只有四问皆否，才自定。**这个自上而下的问责顺序，才是“尽量复用”这句原则的可执行形式**——否则“兼容”会退化成一句谁都可以声称的口号。

**组合，而非替代。** 今天缺的不是能互相通信的 Agent，而是当这些 Agent 分属不同组织、不同信任域时，让“谁授权了什么、凭什么、结果谁负责”依然可验证的那一层。CHASI 的全部架构价值集中在这一句上：它不生产新的智能，它生产**跨域可验证性**。

## 11. Compliance Hub 的八项核心能力

这八项不是八个小功能，而是**一条链上的八个环节**：从“你是谁”到“你能被发现”。任何一环缺失，后面的都不成立。

| # | 能力 | 做什么 | **不做什么** |
|---|---|---|---|
| 1 | 身份与解析 | 让任一主体（人／Agent／组织／群组）在跨域范围内被解析并给出其当前状态；**并让需要被指称的非主体资源（服务／工具／数据）也能被解析** | 不规定主体必须采用哪一种身份体系；**也不把非主体资源当作主体——它可以被命名，不能被授权** |
| 2 | 组织与治理 | 承载权威的来源、成员归属、治理动作的记录 | 不替组织决定它自己内部怎么治理 |
| 3 | 授权与委托 | 让授权可声明、可限制、可撤销、可追溯，支持逐层子委托 | 不代替人做授权决定，也不扩大已授予的授权 |
| 4 | 群组与协作 | 让分属不同组织的主体在共同规则下协作 | 不引入任何外部群组服务作为核心 |
| 5 | 信任与状态 | 回答“现在还能不能信它”：撤销、降级、暂停、恢复 | 不把“注册过”当作“可信” |
| 6 | 证据与一致性 | 让行动留下可验证的证据，并对规范一致性给出判定 | 不代替司法或仲裁去认定事实 |
| 7 | 合规剖面与分级 | 按产业与风险等级给出差异化要求，而非一刀切 | 不用同一个标准覆盖所有场景 |
| 8 | 发现与名录 | 让合格参与者可被发现、可被检索 | **被发现不等于被信任**，名录不是信任背书 |

**三条读法。**

**第一，这八项有先后，不是并列的功能清单。** 没有身份，组织无从谈起；没有组织与授权，群组协作没有主体；没有证据，信任就只剩平台担保；没有剖面，合规只能靠人逐案解释；没有发现，合格者也进不来。**跳过任何一环去做后面的，都会退化成“又一个平台”。**

**第二，每一项都必须能落到一份可被审阅的文档上。** 一项能力若只存在于产品里、不存在于规范里，别人就无法照着实现，也无法判断自己是否合规——那它就不是能力，是**服务**。能力与规范的分界，正是这套 Hub 能不能被称作“基础设施”的分界。

**第三，八项都要有“不做什么”。** 一个 Hub 的定义，一半来自它拒绝做什么。上表第三列与第二列同等重要：**拒绝，是它不被任何一方收编的唯一保证。**

## 12. Causal Accountability Chain

CHASI 最重要的原创研究方向之一，是把 Agent 行动从“黑盒执行”转变为可验证的因果责任链。

```

Human
  ↓ consent / mandate
Organization
  ↓ delegation
Agent A
  ↓ sub-delegation
Agent B
  ↓ action
Tool / API / Transaction
  ↓
Evidence → Outcome → Accountability

```

最终能够回答的不只是“发生了什么”，而是“为什么发生、谁授权、授权范围是什么、是否超越权限、谁承担责任”。

**先要说清：“因果”比一份日志多了什么。** 三样东西常被混为一谈，差别却是决定性的：

| | 回答的问题 | 性质 |
|---|---|---|
| 调用链 trace | 调用了谁、耗时多少、在哪失败 | 技术事实 |
| 审计轨迹 audit trail | 发生了什么 | 已发生的事实 |
| **因果责任链 causal chain** | **凭什么这件事可以发生、谁有权让它发生、有没有越界** | **正当性的推导** |

审计日志记录**事件的顺序**；责任链记录**授权与行动之间的推导关系**。前者能告诉你“Agent B 在 14:03 发起了一次转账”；后者要能告诉你“Agent B 之所以可以发起，是因为 A 从组织取得了范围 R 的授权、又把 R 的一个子集委托给了 B，而这次调用没有超出那个子集”。

**链上每一环必须携带的东西**（缺一则该环不成立）：

- **主体**——是谁；
- **授权依据**——凭谁的什么权力；
- **范围**——能做什么，以及**明确地不能做什么**；
- **时间与有效期**——何时生效、何时失效；
- **委托深度**——这是第几层委托，离最初的权威还有几跳；
- **约束条件**——在什么条件下才允许；
- **证据引用**——这一环凭什么被相信。

**链会在五种地方断**——而这五种都不是异常，是常态：

- 授权来源不可解析（主体已消失或被撤销）；
- 子委托超出了母授权的范围；
- 跨域时对端不承认这种授权形式；
- 时间错位（授权已过期而行动仍在发生）；
- 证据缺失或被单方独占。

**所以关键不在于“保证不断”。**

**核心设计判断：一条诚实的断链，比一条伪造的完整链有价值得多。** 因此因果责任链的目标不是“永不中断”，而是**断了必须能被看见**：缺的是哪一环、缺在谁那里、缺的是什么，都要能被指出来。**一个能报告自己在哪里不完整的系统，比一个永远显示“完整”的系统可信。**

**哪些可验证，哪些只能声明。** 授权范围、时间、撤销状态、委托深度——可验证。意图、善意、“我已经尽力了”——只能声明。把两者混在一起谈，是责任链最常见的一种失效：**声明被当成了证明**。CHASI 的立场是把可验证的部分做到最小充分，然后**明确标出剩下的部分属于声明**——而不是用一套漂亮的可视化，把声明包装成证明。

**责任的终点必须是人或法人，不能是“系统”。** 自动化可以把行动的链条拉长，但不能把责任稀释掉。链的终点必须落在一个能够承担责任的主体上：一个人、一家组织、一个明确的法人实体。**当答案变成“是模型自己决定的”，那就说明责任链断了，而不是责任消失了。**

## 13. Societal Memory：Agent Society 的公共记忆

Agent Memory 是个人记忆；Societal Memory 是共同记忆。**两者不是“一个的放大版”，服务的对象不同**：个人记忆服务于“我记得我做过什么”，社会记忆服务于“**我们共同认定发生过什么、依据什么规则、后来为什么改了**”。

一个成熟的 Agent Society 需要保存六类记忆，而每一类的**写入者、读者、寿命都不相同**：

| 记忆 | 内容 | 谁写 | 谁读 |
|---|---|---|---|
| Event Memory | 发生过什么 | 当事方 | 与事件有关系的人 |
| Decision Memory | 为什么做出这个决定 | 做出决定的主体 | 受该决定影响的人 |
| Commitment Memory | 谁承诺了什么 | 承诺方 | 被承诺方 |
| Policy Memory | 规则何时、为何改变 | 有权改规则者 | 受该规则约束的人 |
| Evidence Memory | 行动依据什么 | 行动方 | 需要核验的人 |
| Dispute Memory | 争议如何产生与解决 | 争议程序 | 当事方与监督者 |

**社会记忆不是“永久保存一切”。** 这一点与直觉相反。要区分两件常被混为一谈的事：**必须可验证**（能核对它没有被改过）与**必须可取得**（内容谁都能读到）。一个成熟的设计可以让内容本身不可读，而“它没有变过”依然可验证——**“记得”不等于“看得见”**。把这两件事解开，公共记忆与隐私才不必二选一。

**可验证记忆不等于区块链。** 区块链解决的是“顺序与不可篡改”，代价是全量复制与全公开。社会记忆真正需要的是三样：**可验证、可控披露、可遗忘**——而区块链只给出前一半，且在最难的地方（**谁来删、按谁的规则删**）恰好帮不上忙。因此方向是**锚定而非上链**：把“某份记录在某时刻的状态”锚定在公开处，让篡改可以被发现，而记录本身留在它的权利人手里，按需、按权限、最小披露地出示。

**允许对同一事件有不同的记忆。** 中心化数据库有一个隐含假设：“只有一个正确版本”。但分歧才是常态：双方对同一次交易的理解可能都诚实，却不一致。因此社会记忆不应假装只有一个版本，而应保存**多个来源的记录以及它们之间的分歧**，把裁定交给争议程序，而不是交给恰好拥有数据库的那一方。**谁拥有数据库，谁就拥有历史——这正是要避免的。**

**Federated，而不是 central。** CHASI 的方向不是建立一个中心化的“全知数据库”，而是探索可验证、可授权、最小披露的 Federated Societal Memory：每个组织保有自己的记忆，跨域时只交换必要的那一部分，并让“交换过什么”本身也留下痕迹。

**与责任链的关系。** §8 的责任链回答**某一次行动**，社会记忆回答**这一类事情我们共同记得什么**。前者是纵深的（一次行动的那条链），后者是横向的（所有主体共享的那一层底）。缺了前者，记忆无从核对；缺了后者，每一次行动都要从头举证。**两者合起来，才是“可验证的社会”。**

## 14. CHA2A 与 CHASI 的关系

建议把 CHA2A 与 CHASI 分成两个层次。

```

CHASI   Compliance Hub for Agent Society Infrastructure
  │
  │   Governance · Identity · Delegation · Federation
  ↓
CHA2A   Agent-to-Agent / Agent Society Architecture & Protocols

```

CHA2A 可以继续发展为具体的 architecture、protocol、profiles 和 extensions；CHASI 则承担更高层的 Vision、Governance、Compliance Framework、Research Hub 和生态连接。

这样既可以保持技术工作的独立性，又能够让 ComplianceHub.cn 成为一个长期的公共研究与生态入口。

## 15. CHASI 与现有生态的关系

- **A2A / AAIF**——Agent-to-Agent interoperability。
- **OpenA2A**——开放 Agent interaction / protocol research。
- **MCP**——Agent-to-tool / resource connectivity。
- **DID / VC**——decentralized identity 与 verifiable credentials。
- **OAuth / OIDC**——成熟的 authentication / authorization 基础。
- **NANDA**——Agent Internet discovery、registry 与 infrastructure research。

## 16. 长期形态

如果这件事做成，十年后它应该是一份**可以被引用的公共记忆**：某个智能体社会许过什么、规则何时因何而变、争议如何了结、公共利益如何被守住。

**不是为了追溯审判**——是为了让“**当时的人为什么认为那是允许的**”有据可查，也让“下一次可以怎么做”有先例可循。

**记忆是社会得以延续的形态；上面那七个条件，是它的第一层地基。**

## 17. 边界：明确不做，以及各自的条件

- 支付与结算
- 市场与挂牌
- 行为监控与内容合规
- 跨真实注册表的联邦
- 高级别的生态信任态

**每一项在框架分册里都写了它需要的条件。** 不列在这里，是因为**它们是决定，不是空白**——写成“不做”是对的，写成“留待将来”也是对的，**唯独不能什么都不写**。

## 18. 本件的状态与它自己的规矩

**实验性。** 本件是立场（vision），会随认识改变而改；CHASI 的规范件是另一批，各有版本、各有判定方式。

**本件不规定任何人必须做什么。** 若本件与规范件冲突，以规范件为准。

**它是 living 的**：立场可以反复，痕迹不可以——所以每一次实质改动都提升版本号；
而**改动说明只在该版所取代的版本曾经公开之后才写**。

**本件不设仓级变更日志。**

## 结语

如果 CHA2A 是我们对于 Agent Internet / Agent Society 的技术探索，那么 CHASI 可以成为更大的 Vision：一个不属于任何单一公司、平台或 Agent Runtime 的开放治理枢纽。

它不是为了控制 Agent，而是为了让自主性、信任、责任和自由能够同时存在。

从这个意义上说，Compliance 不是限制 Agent Society 的力量，而是使这种社会真正能够规模化存在的基础条件。

—— CHASI Vision · v2.12
