# Agent 动作授权剖面

> 状态：起草稿（v0.1）| 日期：2026-11-21 | 层级：**L4 · 剖面**
>
> 本剖面约束依赖方如何把持久授权、当前观测、操作契约和证据，收敛为一次
> agent 尝试动作的决定。它复用 Passport、Registry、Organization、Group
> 和证据对象，不定义身份方法、凭证格式、策略语言、传输协议或执行协议。

## 1. 范围

本剖面回答一个问题：

> 此时此刻，这个 agent 能否代表这个 principal，在此上下文中尝试这个动作？

它把经常被合并的四个时间尺度分开：

| 对象 | 时间尺度 | 回答的问题 |
|---|---|---|
| 身份 | 持久或本地 | 这是哪个主体 |
| 鉴权 | 本次呈现 | 此刻是谁提出了该主张 |
| 持久授权 | 任务窗口 | 该 agent 在整个任务中可持有什么权限 |
| 动作决定 | 一次尝试动作 | 此刻是否允许这个动作 |

执行尝试是第五层：它记录授权之后实际尝试了什么。执行回执不是决定，也不证明
最终完成。

## 2. 非目标

本剖面不：

- 重定义 DID、VC、A2A、MCP、OAuth、GNAP 或 Registry API；
- 规定决定的线上格式；
- 判断法律责任或监管合规；
- 分配统一信任评分；
- 替代 Passport 验证流程；
- 替代组织或群组治理；
- 要求唯一中心策略引擎；
- 要求每个动作都进行人工审批。

## 3. 术语

| 术语 | 本剖面含义 |
|---|---|
| **持久授权** | agent 在任务窗口内持有的权限，来自 Passport 授权、委托、角色或其他被承认的权威来源 |
| **操作契约** | 应用侧声明：一次操作需要哪些输入、提交前后执行哪些检查，以及输入缺失、过期或冲突时如何处置 |
| **决定输入** | 决定点读取的对象，连同来源、版本、范围、观测时间和覆盖情况 |
| **验证结论** | `valid`、`invalid` 或 `indeterminate`，沿用本族既有裁决词 |
| **依赖方动作** | `allow`、`remediate`、`deny`、`escalate` 或 `indeterminate` |
| **未作决定** | 必需检查未执行或没有形成决定；它不是依赖方动作，也不是验证结论 |
| **控制面变更** | 改变未来决定输入的授予、暂停、恢复、撤销或到期 |
| **观察到的效果** | 独立观测显示控制面变更确实到达执行点 |

## 4. 决定模型

```text
持久授权
  + 身份 / 鉴权状态
  + 请求动作
  + 操作契约
        |
        v
收集并固定决定输入
        |
        v
验证结论
  valid / invalid / indeterminate
        |
        v
依赖方动作
  allow / remediate / deny / escalate / indeterminate
        |
        v
决定记录
        |
        +----> 未作决定，单独记录
```

验证结论描述证据能够确立什么；依赖方动作描述依赖方准备如何处理。两者不能
互相替代。

## 5. 操作契约

操作契约针对一类操作说明：

- 操作是什么，以及提交它的后果；
- 消耗哪一份持久授权或权威来源；
- 提交前需要哪些决定输入；
- 提交后需要哪些观测；
- 提交前后各执行哪些检查；
- 每一项检查由谁负责；
- 每个输入声明的范围、覆盖和新鲜度预算；
- 输入缺失、过期、不可达或冲突时如何处置；
- 是否需要人工审批，以及约束审批的证据；
- 单次操作的最长持续时间和继续检查点。

操作契约不授予权限。它只说明权限和其他输入必须如何被检查。

一个没有声明任何权威来源的操作不能自行确立授权。一个没有写明必需输入失败
处置的操作契约，对该操作是不完整的。

## 6. 决定输入

决定点必须为每个必需输入保留：

- 读取的对象或主张；
- 来源；
- 版本或 revision；
- 观测范围与覆盖；
- 观测时间；
- 取回或解析时间；
- 来源直接断言，还是适配器观测；
- 任何未决、过期或冲突成分。

当适用剖面要求负向权威或状态结论时，决定记录还必须保留权威依据：来源、范围、
覆盖、时间基准、适用时的联邦路径和残留限制。

无法取得的输入不得用应用自报标识或默认值替代，然后写成已验证。

## 7. 验证结论

| 结论 | 含义 |
|---|---|
| `valid` | 在适用剖面下，本次动作和决定时刻所需的全部主张均成立 |
| `invalid` | 有权威依据确认某个必需主张为假、已撤销、越权或不适配 |
| `indeterminate` | 因证据缺失、不可达、过期、冲突或超出已确立覆盖，无法确立某个必需主张 |

政策不得把 `invalid` 变为 `valid`。

`indeterminate` 不得报告为 `valid`；一个可达但覆盖不足的来源，也不得被当成
权威负向结论。

本剖面使用 CHASI 既有裁决词。若实现内部使用
`verified / unresolved / rejected`，映射为：

```text
verified   <-> valid
rejected   <-> invalid
unresolved <-> indeterminate
```

该映射不授权依赖方动作改写验证结论。

## 8. 依赖方动作

| 动作 | 含义 |
|---|---|
| `allow` | 在本决定下可以继续 |
| `remediate` | 暂缓，并修正可补救的输入、审批或动作参数后重新评估 |
| `deny` | 不得继续 |
| `escalate` | 转交有资格的人员、权威或专业流程 |
| `indeterminate` | 根据当前输入，决定点无法确定安全动作 |

`remediate` 必须说明需要修正什么，以及重新评估的条件。`escalate` 必须说明
接收方和范围。`indeterminate` 必须保留仍未解决的内容。

任何依赖方动作都不得把 `invalid` 转为 `allow`。
`indeterminate` 不得因为动作紧急或无人处理而自动升级为 `allow`。

### 8.1 默认参考映射

| 验证结论 | 默认依赖方动作 |
|---|---|
| `invalid` | `deny`；可以为调查或补救而升级，但不得允许动作 |
| `valid` 且政策满足 | `allow` |
| `valid` 但本地政策不满足 | `deny`、`remediate` 或 `escalate` |
| `indeterminate` 且输入可补救 | `remediate` |
| `indeterminate` 且不存在补救路径 | 按声明政策 `deny`、`escalate` 或 `indeterminate` |

该表是参考剖面。部署可以采用更严格政策，但不得把 `invalid` 或
`indeterminate` 转为 `allow`。

## 9. 未作决定

“未作决定”是独立记录状态，适用于：

- 没有到达决定点；
- 必需检查没有执行；
- 服务在形成结论前失败；
- 政策没有授权任何人作出决定。

未作决定记录必须说明：

- 尝试的动作；
- 缺失的检查或决定；
- 负责角色或服务；
- 观测时间和来源；
- 外围系统实际采用的处置。

如果外围政策停止了动作，该停止是独立的依赖方动作或控制面行为，不反向生成
一个验证结论。

## 10. 持久授权生命周期

持久授权可以处于：

```text
授予 -> 有效 -> 暂停 -> 有效
                \-> 撤销
       \-> 到期
```

具体表示由适用权威来源拥有。本剖面要求决定点在重要动作前重新评估当前适用性。

决定必须记录所使用的持久授权版本或观测。来源在长任务中变化时，操作契约声明
继续检查点；决定点在这些点重新读取来源。

对于变更前派发、变更后启动的 worker：

- worker 的首次检查记录它读取的版本；
- 父派发记录保留父决定使用的版本；
- 任何一方不得继承另一方的时效。

## 11. 控制面变更与观察到的效果

控制面变更有三个不同状态：

1. **已记录**：权威来源记录变更；
2. **已确认**：执行点或平台报告收到；
3. **已观察到效果**：独立观测显示后续决定不再使用被替代状态。

撤销“已记录”不能单独证明所有决定点都停止接受被撤销权限；确认回执也不能单独
证明效果。

本剖面不定义控制面协议，但要求部署说明：

- 哪些决定点必须收到变更；
- 生效允许的最大时间；
- 如何度量覆盖；
- 决定点断连时如何处理；
- 如何检测和记录冲突副本。

## 12. 人工审批

当操作契约或适用政策要求人工审批时，审批证据必须绑定：

- 精确动作或动作摘要；
- principal 和行动中的 agent；
- 操作契约版本；
- 实际展示给审批人的摘要；
- 审批人角色和权限；
- 决定结论和原因；
- 有效期；
- 是否由 agent 或利益相关方自批。

未绑定具体动作的审批，不得复用于实质不同的动作。

## 13. 决定记录

决定记录至少保留：

| 成员 | 用途 |
|---|---|
| `decisionId` | 标识一次决定事件 |
| `actionDigest` | 绑定尝试动作 |
| `contract` | 操作契约标识、版本和摘要 |
| `principal` / `agent` | 代表谁、由谁行动 |
| `processInstance` | 区分不同任务运行 |
| `executionInstance` | 区分同一流程内的重试或重复执行 |
| `inputRefs` | 固定每个必需输入的来源、版本、时间、范围和覆盖 |
| `verificationOutcome` | `valid`、`invalid` 或 `indeterminate` |
| `policyAction` | 所选依赖方动作；未作决定时不出现 |
| `reasonCodes` | 分别保留每个独立原因 |
| `policyProfile` | 政策和剖面标识、版本 |
| `verifier` | 验证实现或权威 |
| `decidedAt` | 决定时间 |
| `unresolved` | 所有仍未解决项 |
| `noDecision` | 仅在未形成决定时出现 |

两个动作若在操作契约声明的任一动作描述字段上不同，不得生成相同的规范化动作
绑定。内容绑定与发生绑定是两个独立性质。

## 14. 失败语义

决定点必须区分：

- 声明覆盖内未找到对象；
- 来源不可达；
- 来源无法为相关范围确立覆盖；
- 多个必需来源冲突；
- 找到对象且权威结论为否定；
- 找到对象但状态过期；
- 检查未执行；
- 已决定但未尝试执行；
- 已尝试执行但结果未知；
- 已收到执行回执，但最终性未确立。

这些状态不得压成一个布尔值。

## 15. 一致性

最小一致性场景：

1. 有效授权、政策满足、状态新鲜且动作摘要匹配，产生 `valid` / `allow`；
2. 已确认撤销产生 `invalid` / `deny`；
3. 状态不可达产生 `indeterminate`，绝不产生 `valid`；
4. 权威覆盖不足产生 `indeterminate`，不是 `invalid`；
5. 权威确认越界产生 `invalid`；
6. 动作摘要不符或重放产生 `invalid`；
7. 身份已验证但没有覆盖该动作的授权，不得产生 `allow`；
8. 验证有效但本地政策不满足，不得自动产生 `allow`；
9. 针对其他动作展示的审批，不得满足本动作；
10. 控制面变更已记录但没有观察到的效果，不得报告为已生效；
11. 必需检查未执行，产生未作决定记录，不是 `indeterminate`，也不是 `deny`；
12. 内容不同的两个动作，不得共享相同规范化动作绑定；
13. 内容相同的重试，执行实例仍可区分，内容绑定保持稳定。

任何公开一致性套件中，负向案例宜多于正向案例。每个向量应指出它测试的要求和
预期原因代码。

## 16. 与其他剖面的关系

- **Passport** 提供身份、权威、委托和验证对象；本剖面消费它们。
- **Registry Interop** 提供状态、覆盖和取回观测。
- **Agent Card Identity** 提供发现引用，不提供动作授权。
- **Organization Governance** 提供组织角色背后的权威。
- **Group Collaboration** 提供协作上下文和成员资格。
- **Evidence Record** 确立决定之后实际发生了什么。

本剖面不把 Passport 变成动作执行器，也不把 Registry 变成决定点。

## 17. v0.1 决定

- 持久授权与动作决定分开；
- 操作契约说明检查和失败处置，但不授予权限；
- 验证结论与依赖方动作分开；
- 未作决定是独立记录状态；
- 依赖方动作为 `allow`、`remediate`、`deny`、`escalate` 和
  `indeterminate`；
- 不要求编码、传输、策略语言或中心引擎；
- 运行时证明和跨平台干预协议留在本版之外。
