# 术语表 —— 用词卷

> 状态：草案（v0.3）
> 日期：2026-10-31
> 定位：本族**术语的单一来源**。凡与本草冲突的用词，以本草为准
> 原则：**一个概念一个词**——同一个东西在两处用两个词，就是两处可能各判一次
> 相关：全部各册

---

## 1. 本草怎么用

三个栏目：

| 栏 | 意思 |
|---|---|
| **正名** | 本族规定的唯一写法 |
| **禁用** | **不得用来指这个概念**的词 |
| **为什么** | 简述区分的依据 |

**只列有分歧风险的词。** 一个词在全族本来就只有一个意思、只有一种写法的，不入表——否则本草会膨胀成词典。

**「禁用」不等于「这个词不能用」**，而是**不能用它来指这个概念**。例如「断言」这个词可以用，但不能用它来指「声明」。

**本草不含概念的定义。** 定义在各册；本草只固定**写哪个词**。

## 2. 实测出的冲突，以及处置

以下四处是**实测**的（不是设想的），本草**同时改掉了非正名的一侧**：

| # | 冲突 | 处置 |
|---|---|---|
| 1 | `集体`（`naming.md`）vs `群体`（Vision §1） | 统一为 **群体**。Vision 是 L1 且 §1 已给出定义；`naming.md` 已改 |
| 2 | `验证者`（`naming.md`，指 hash）vs `验证方`（各方，指作出判定的那一方） | **两者本非同一概念**：`验证方` 是一方；hash 不是“一方”，它是**校验依据**。`naming.md` 已改 |
| 3 | `凭据`（Vision §4）vs `凭证`（`organization-governance.md`） | 统一为 **凭证** |
| 4 | `构件`（`protocol-suite-architecture.md` §9）vs `件`（全族，185 处） | 统一为 **件** |

## 3. 术语表

| 正名 | 禁用 | 为什么 |
|---|---|---|
| **主体** | `Agent`（作统称时） | §1 区分四类主体：人 · 组织 · agent · 群体。用 `Agent` 作统称会把组织与群体排除在外 |
| **agent** | `Agent`（作成员种类时） | **专名保留大写**（`Agent Society` · `Agent Internet` · `Agent Runtime`）；作成员种类时小写 |
| **群体** | `集体` | 成员种类之一（家庭与社区是它的最小形态）。`Group` 是**协作域的对象名**（见 `group-collaboration.md`），不是成员种类名 |
| **组织** | `Organization`（作中文正文时） | 中文正文用「组织」；字段名与专名用 `Organization` |
| **验证方** | `验证者` | **作出判定的那一方**，与 `question.md` §4「判定人是验证方」同指 |
| **校验依据** | `验证者`（指 hash 时） | hash 是**凭以核对的东西**，不是一个“方”。见 `naming.md` §1 |
| **凭证** | `凭据` · `证书` | 身份与授权类凭证。`证书` 特指 X.509 形态，不泛用 |
| **件** | `构件` · `组件` | 本族的术语（「用别人的件、但要满足什么」，见 `assembly.md`）。`artifact` 仅当指既有对象名时保留英文 |
| **记录** | （无禁用；须加限定） | **有三义**：① 实验记录（一次实验的发现，Vision §9）② 责任链记录（一次行动的授权推导，Vision §12）③ 社会记忆（六类，Vision §13）。**单说「记录」必指其中之一** |
| **判定** | `评级` · `认证` | 本族**只给判定格式，不做评级、不做认证**（Vision §11 能力 6／7／8）。三者不是同义词；混用会把本族读成监管方 |
| **名录** | `注册表` | **名录收录声明，注册表裁定事实**（Vision §6）。本族持名录，不持注册表 |
| **注册表** | `名录` | 同上——承载主体状态并为其作答的那一方所运营的东西 |
| **合规** | （无禁用；须指回可核验） | 本族不做合规判定。Vision §5 已定义名字里的 Compliance 指**使可核验成立所需的那些条件**（§3①） |
| **可核验** | `合规`（作同义时） | §3① 的条件名 |
| **槽** | `位` · `插槽` | `assembly.md` 的 S1–S4 |
| **剖面** | `profile`（作中文正文时） | L4 的层名：叠在其下各层之上的约束 |
| **够用判据** | `完成判据` | 每一层、每一册写明「满足什么即视为完备，不再扩写」（`protocol-suite-architecture.md` §4） |
| **授权依据** | `权威依据`（当指每一环的授权来源时） | **两词不同义，不得互换**：`授权依据` 是责任链**每一环**的字段（Vision §12 七项之一）；`根权威依据` 是 L3 四层分解的**第四层**。前者须能沿后者回溯到起点 |
| **根权威依据** | `授权依据` | 同上 |
| **权威依据** | `授权依据`（当指判定所依赖的权威来源时） | 验证结果中用于说明结论来源、覆盖范围、时间、联邦路径和限制的依据；不得替代责任链每一环的授权依据 |
| **声明** | `断言` · `自证`（混用） | `声明`＝当事方作出、**可被核对**；`自证`＝对自己作出（`assembly.md` 要求的形态，是否成立由验证方判）；`断言`＝没有可核对依据的说法，是本族要消除的东西（Vision §12「声明被当成了证明」） |
| **承诺** | `承诺书` | `naming.md` 四类对象之一；**对象模型未定**，本草只固定它的寻址方式 |
| **规则版本** | `政策版本` | `naming.md` 四类对象之一；政策只是规则的一种 |
| **验证器** | `验证方`（指作出判定的那一方时） | 一段**实现或工具**（如「双验证器互锁」里的那两个），**不是一个「方」**。作出判定的那一方是「**验证方**」 |
| **分级 · 等级 · 档位** | `评级`（作同义时） | §11 能力 7 名为「合规剖面与**分级**」（grading）——它**声明需要满足什么**，不判定谁达到了；`等级` 是累进值（如 L0–L4），`档位` 是准入档。三者都不得用来指「评级」，见「判定」行 |
| **第三方** | —— | 与 `验证方` 不同：`第三方` 强调**不属于任何一方**（§3① 的措辞）；`验证方` 强调**作出判定**。同一个主体可以两者都是 |
| **逻辑 agent** | `执行实例` | 一个可被持续引用的 agent 身份；不能把一次运行、进程或 worker 当成逻辑 agent |
| **执行实例** | `agent`（指一次运行时） | 某一次具体运行、进程或 worker；不等于逻辑 agent，也不等于主体 |
| **内容身份** | `主体标识` | 包、工件或内容的摘要身份；它回答“运行的是什么内容”，不回答“这是哪个主体” |
| **行动时状态** | `当前状态`（用于替代历史时） | 动作发生时有效的模型、配置、环境和版本；当前状态不能追溯替代行动时状态 |
| **状态不可达** | `撤销` · `无效` | 无法取得状态来源，不等于确认撤销，也不等于确认无效 |
| **原因代码** | `错误码` · `结果`（混用时） | 解释为何得到 verified、unresolved 或 rejected；它不是依赖方动作，也不是另一个验证结论 |
| **依赖方动作** | `验证结论` · `quarantined`（作结论时） | 依赖方依据政策采取的动作；验证结论应先给出，再由依赖方决定动作 |

**够用判据**：全族任一册的用词，都能在本草找到正名或不被本草禁止；本草未收、且确实存在两义风险的词，是本草需要扩充的信号。满足即止，不再扩写。

---

## 4. 本草不做什么

- 不定义概念本身——定义在各册；
- 不收录没有分歧风险的词；
- 不做同义词的**自动替换**——凡本草列出的冲突，都已逐处改掉（§2）；
- 不固定**英文**的写法——除本表点明的几处（专名大写、`agent` 小写）外，英文另有各册自己的体例。
