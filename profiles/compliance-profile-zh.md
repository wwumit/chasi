# 合规剖面

> 状态：草案（v0.1）｜日期：2026-10-19｜层：**L4 · 剖面**——叠在其下各层之上；不为任何分册增加要求
> 定位：按产业与风险等级，声明 `assembly.md` 四个槽各自**必须成立到什么程度**
> 原则：剖面只声明条件，不判定谁达到（Vision §11 能力 7）；判定属于验证方（`question.md`）。
> 关联：`assembly-zh.md`（四槽）· `../specs/naming-zh.md` §2.2（规则版本）· `../specs/question-zh.md`（判定）· `../specs/organization-governance-zh.md` · `../specs/group-collaboration-zh.md`（准入）

---

## 1. 问题与出路

**问题**：合规要求容易被一刀切——同一套要求套到所有产业、所有风险等级上。一刀切的结果只有两种：**要么过重**（小规模部署达不到），**要么过轻**（高风险场景也照样通过）。

**出路**：把**合规剖面**做成一等对象——一份**有版本的声明**，按产业与风险等级写明四槽各自要满足到什么程度。**剖面本身不判定任何人。**

---

## 2. 剖面规定什么

- **剖面是规则版本**：带 hash 与 `effective_from`，修订追加（`naming.md` §2.2）。
- **剖面只声明**：它说什么必须成立，从不说谁达到了。
- **剖面可被引用**：Passport、准入记录、检查报告都指向**作出时生效的那一版**。
- **剖面不引入原语**：它约束 `assembly.md` 的四个槽；不定义标识、不定义权威模型、不定义记录格式。

---

## 3. 对象

| 字段 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `profileId` | string | ✔ | 稳定标识 |
| `profileVersion` | `{hash, effective_from, uri?}` | ✔ | 规则版本（`naming.md` §2.2） |
| `industry` | string[] | ✔ | 产业标签；`*` 表示跨产业 |
| `riskBand` | enum | ✔ | 风险等级；本件固定语义，取值由部署方定 |
| `slots` | object | ✔ | S1–S4 各自的约束 |
| `disclosure` | object | ✔ | 可取得什么，由谁取得 |
| `review` | object | ✔ | **复查条件**，不是复查日期 |
| `status` | enum | ✔ | `draft` · `active` · `withdrawn` |

**够用判据**：一个不属于任何一方的第三方，只凭这个对象，就能说出某一产业与某一风险等级下适用哪几条四槽条件，并找到某一时点生效的那一版。

---

## 4. 剖面可以对每个槽约束什么

| 槽 | 剖面可以要求 | 剖面不可以要求 |
|---|---|---|
| **S1 标识** | 解析不依赖被验证方在线；信任根可携带 | 指定某一种 DID 方法 |
| **S2 权威链** | 可回溯到起点；范围可与行动比对 | 规定一个组织内部怎么治理自己 |
| **S3 规则版本** | 以动作发生时生效的那一版为依据 | 指定某个法规数据库或厂商 |
| **S4 记录** | 第三方可复算；责任终点落在人或法人 | 要求留存一切 |

**表中任何一条都不得削弱 ①（可核验）。** 较低的风险等级可以要求得更少，但**不得少到四问答不出来**。

---

## 5. 风险等级

本件不固定数值尺度，只固定三件事：

1. **等级是场景的属性，不是主体的属性。** 它与 L0–L4 不是同一条轴——后者描述的是"关于一个主体已经证明了多少"。
2. **声明等级的人必须给出依据。** 没有依据的等级是一个标签，不是一条声明。
3. **不同等级可以要求不同的证据集**，但更低的等级**从不降低 ①**。

---

## 6. 与准入、判定的关系

准入使用剖面：接收方按**自己声明的那份剖面**核对材料，然后作决定。**决定留在接收方**（`overview.md` §4.4 R3；`group-collaboration.md` §4.3）。

**剖面不是准入门槛。** 它由验证方或接收方选用；本族不把某一剖面强加给所有人。

---

## 7. 本件固定的，与留给部署方的

| 本件固定 | 留给部署方 |
|---|---|
| 对象的字段与必填性 | 产业分类法 |
| 规则版本的形式（hash ＋ `effective_from`） | 风险等级的取值 |
| 每个槽可以／不可以要求什么 | 各个域采用哪一份剖面 |
| 较低等级从不降低 ① | 各等级对应的披露集 |

---

## 9. 本件不做什么

- 不判定谁达到某份剖面；
- 不固定数值化的风险尺度；
- 不定义策略语言；
- 不点名任何法规数据库或产品；
- 不替代 `organization-governance.md` 或 `group-collaboration.md` 的准入规则。

---

本剖面叠在其下各层之上，不为任何分册增加要求；部署方选择使用时，它约束四个槽。
