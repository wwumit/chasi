## 0. 定位

**Compliance Hub 是支撑跨主体参与、身份核验、授权与问责的基础设施层，不是合规信息展示站。**

网站是这一层的一个客户端，不是这一层本身。

## 2. 它要回答的问题

只回答「你是谁」的 Hub 是一个目录。这套架构要承载的是一条链：

**身份 → 权威 → 策略 → 行动 → 证据 → 问责**

每一个箭头都是一次交接，**记录必须能跨过这次交接**。记录无法跨过交接时，链在该处中断；中断本身应作为可核验的发现记录。

---

## 3. 设计原则

| # | 原则 | 它定下什么 |
|---|---|---|
| 1 | **合规使自主成为可能** | 合规用来赢得信任、扩大正当的自主；它不只是限制 |
| 2 | **联邦优先于集中** | Hub 与组织 Hub、伙伴 Hub 协作，不成为普世的中心权威 |
| 3 | **证据优先于断言** | 有后果的主张由可核验的证据承载，不由一句声明承载 |
| 4 | **策略感知的自主** | 授权是上下文相关、有范围、受策略约束的 |
| 5 | **以人为中心的问责** | 自主行动始终连着一个人或一个法人 |
| 6 | **协议中立** | 复用 A2A、MCP、DID/VC 等成熟技术 |
| 7 | **实现自由** | 先标准化语义与互操作点，再谈内部实现 |
| 8 | **渐进信任** | 准入与授权可以基于不同等级的证据 |
| 9 | **生命周期治理** | 合规是连续的：注册、准入、行动、监控、审计、续期、撤销 |

## 5. 组件

### 5.1 身份与注册表

为 agent、人、组织、群体、服务与权威维护标识与注册记录。解析、状态与撤销由身份绑定承载；本件不定义它们。

### 5.2 可携带声明（Passport）

身份、主体、能力、角色、授权、证明，以及**指向证据的引用**的可携带表示。

**它携带引用与声明，不携带证据本体。** 把一切装进去的 Passport 会变成一个中心数据容器，与原则 2 相悖。

> Passport 的字段级定义与验证流程是**另一份 working draft**。本件只定义这个组件在架构中的位置。

### 5.3 治理

组织治理、群组治理、成员资格、角色、规则、决定、争议与人的覆盖。

### 5.4 策略

约束准入、授权、委托、数据访问、交易与行动的策略。**尚未成文**（见 §13）。

### 5.5 委托与授权

谁授权了这个 agent、委托了什么、范围、条件、期限、限制，以及是否允许继续向下委托。

**范围必须写到能与行动比对的粒度。不能与行动比对的范围，是声明，不是授权。**

### 5.6 证据与证明

支持身份、能力、策略遵守、行动、认证与治理决定的证据。记录**内容寻址**；注册表只存摘要，不存正文。

### 5.7 问责与审计

连接主体、授权、agent、行动、策略与证据的记录。**链的终点落在人或法人**；终点写成「系统」的，是缺环，不是答案。

### 5.8 联邦

独立的 Hub 与注册表建立信任关系，交换跨域参与所需的最小信息。**承认仍是各方的本地策略。**

---

## 6. 运行生命周期

```
注册 → 核验 → 准入 → 授权 → 行动 → 监控 → 证据 → 审计 → 续期 / 撤销 → 再授权
```

合规是生命周期，不是一次性的认证事件。同一个 agent 可以在不同的社会里有不同的权限，并随策略、身份、成员资格或证据的变化而获得或失去权威。

---

## 7. 合规即准入

一个想加入群组、组织或社会的 agent，出示身份、可携带声明、能力与证据。接收方的治理域按自己的策略评估这些材料，并决定它能否参与、在什么条件下参与。

```
身份 → Passport → 能力 → 策略检查 → 治理检查 → 证明 → 准入
```

合规在这里从文档变成**运行期机制**。**决定属于接收方**；Hub 提供材料与记录，不提供裁决。

---

## 8. 多重治理范围

同一个 agent 同时受个人策略、组织策略、群组策略、服务策略与更宽的监管要求约束。

```
个人策略
      ↓
组织策略 ↔ 群组策略 ↔ 社会策略
      ↓
agent 授权 / 行动
```

因此**策略优先级、冲突解决、委托边界与人的覆盖，是架构议题**，不是可选的管理功能。

---

## 9. 联邦

```
                    联邦层
                       │
        ┌──────────────┼──────────────┐
        │              │              │
  ComplianceHub.cn  组织 Hub       伙伴 Hub
        │              │              │
      Agents         Agents         Agents
```

不同的身份、策略、平台与协议。Hub 可以是参考点或协调点，但不成为唯一的权威。联邦必须定义信任建立、发现、声明交换、证据引用、授权语义与撤销——**除身份绑定已经定下的部分之外。**

这条分界保住两件事：**跑得快**，以及**通向标准的路仍然可信**。

## 12. 最小闭环

最小实现不去一次做完整个平台。一个可用的闭环是：

1. agent 与组织的注册表；
2. agent 的可携带声明；
3. 群组成员与治理记录；
4. 有范围的授权与委托；
5. 证据与证明的引用；
6. 行动与问责事件；
7. 简单的策略评估；
8. 一个基础的联邦接口。

目标是**先跑通一个完整的跨组织治理闭环**，再扩组件集。参考场景是跨组织群组协作（`group-collaboration.md`；用例 01 在 `../method/use-case-laboratory-zh.md`）。

## 14. 架构命题

跨主体的自主参与需要一组可核验的机制，把身份、权威、策略、证据与问责连接起来。

合规通过可核验的约束扩大可被信任的自主范围，是这一基础设施的组成部分。
